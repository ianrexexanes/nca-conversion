# The /cro research procedure

This is the procedure `/cro research` follows. It writes the plugin's folder as `${CLAUDE_PLUGIN_ROOT}` and its data folder as `${CLAUDE_PLUGIN_DATA}`. The shell sets neither one, so put the full paths the `cro` skill gave you in their place in every command you run and every file you read. Any argument that can hold a space, such as a project folder or a page name, goes in double quotes. Work through the steps in order. The output is the Conversion Brief, named and laid out as `audience-research` already does (see its "Where the brief goes"), in the project folder, else wherever the project keeps copy.

1. Mode per page. Ask Search or Direct, one answer per page; a group of pages, such as all service pages, can share one. Definitions: `${CLAUDE_PLUGIN_ROOT}/skills/cro/references/modes.md`. For a Search project, keyword research comes first: run it through claude-seo's `seo-dataforseo` skill when it is installed, else take the user's own result. Record it per page and per language in the brief's `## Page modes and keywords` table: keyword, variants, volume, difficulty, tool, date checked. The plugin never picks a keyword; the user decides whether it can be won. A page whose research is not done is recorded as "mode pending: keyword research", and no copy is written for it.
2. Traffic and awareness, two separate answers, written in `## Traffic and awareness`. Name the traffic source. Awareness is cold (problem-aware) or warm (solution-aware); it picks the hero and whether pain or proof comes first, and it is asked beside the mode, never read from it. The second answer is temperature: cold, warm or hot, with the offer that suits it: a small first step for cold, a deeper one for warm, the paid step itself for hot.
3. For an existing page, take a first look. Run `python3 ${CLAUDE_PLUGIN_ROOT}/skills/conversion-page-audit/scripts/page_facts.py <url> --out <dir>/facts.json` and `${CLAUDE_PLUGIN_DATA}/venv/bin/python ${CLAUDE_PLUGIN_ROOT}/skills/cro/scripts/render_check.py <url> --out <dir>/render`, with `<dir>` a folder for this research's files. Rendered evidence comes only from `render_check.py`. Answer the four above-the-fold questions in order: What's in it for me? Is it for me? Does it work? What do I do next?
4. Mine the voice of customer, through `${CLAUDE_PLUGIN_ROOT}/skills/audience-research/references/voice-of-customer-mining.md`. Keep the customers' own words, with where each came from.
5. Behaviour data, where the site has it, as exports the user supplies, never invented; `/cro data` is not built yet. What is missing goes to `## Open and unconfirmed`.
6. Personas and jobs, through `${CLAUDE_PLUGIN_ROOT}/skills/audience-research/references/persona-and-jtbd.md`.
7. The offer, broken into value propositions through `/cro offer`.
8. The `## Proof available` section: a table of each item, its source, whether it may be shown, and where it goes (`prooftop`, the strip, beside a button, the wall). Proof is never invented; a missing item is a gap, written `NOT ESTABLISHED — <what it would take>`.
9. The `## Visual inventory`: the real product shots, screenshots and team photos the page can use, never stock. What is missing is a gap, written the same way.
10. The NotebookLM route, when it is available, as `${CLAUDE_PLUGIN_ROOT}/skills/audience-research/references/research-modes.md` describes it. Otherwise write `- NotebookLM: skipped, because <reason>.` in the brief's `## Open and unconfirmed` list.
11. Write the brief with the `audience-research` template. Copy is finished before the design tool opens.
